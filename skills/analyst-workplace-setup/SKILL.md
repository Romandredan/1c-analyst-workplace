# Рабочее место аналитика: проверка и установка

Рабочее место собирается по ступеням. Каждый компонент описан в манифесте
[components.json](components.json): зачем он нужен, какой навык или какая работа
его использует, откуда берётся, как ставится (основной способ и запасной без прав
администратора) и как проверить, что он работает.

| Ступень | Что даёт |
|---|---|
| 1 | Чат с пространствами: ничего не устанавливается |
| 2 | Агентская среда: клиент агента, Git, Python, Node.js, Mermaid CLI, pandoc, OpenSpec, навыки аналитика |
| 3 | Контур 1С: платформа, индекс кода конфигурации, шлюз к данным, сборка и тесты |

## Жёсткие границы

- Источники только из манифеста: официальные сайты, репозитории проектов,
  реестры пакетов. Других зеркал и сборок не используй.
- Ничего не устанавливай до подтверждения плана пользователем. Подтверждение
  даётся после того, как пользователь увидел план: «делай», «быстро» или «ставь
  всё» в первом сообщении подтверждением плана не являются.
- Права администратора не запрашивай и не обходи. Если способ требует их, а прав
  нет, переходи к запасному способу без прав или останавливайся.
- Корпоративные ограничения (блокировка загрузки, политика запуска программ) не
  обходи. Сообщи, что именно заблокировано и что просить у службы ИБ.
- Лицензионное ПО (платформа 1С) не скачивай: только инструкция пользователю.
- Секреты, пароли и токены в манифест, версии и отчёты не записывай.

## Порядок

### 1. Цель

Выясни ступень (2 или 3) и клиент агента (`zcode`, `claude` или каталог навыков
явно). Если пользователь готовит место под конкретный навык или вид работы, найди в
манифесте компоненты по полю `used_by`.

### 2. Проверка

```bash
python scripts/check_env.py --stage <ступень> --client <клиент>
```

Скрипт сам перечитывает PATH из реестра, поэтому видит только что
установленное. Для Mermaid CLI он рисует пробную схему с кириллицей: версия без
работающей отрисовки считается отсутствием. Для code-index версии тоже
недостаточно: smoke-проверка гоняет всю цепочку (CODE_INDEX_HOME, daemon.toml,
статус демона, ответ MCP на порту 8011). Бинарник без живого MCP получает
статус «настроить»: покажи его в плане отдельной строкой и продолжай
пост-установкой из раздела ниже. Навык в каталоге `skills-disabled`
не считается установленным.

### 3. План

Покажи пользователю таблицу только недостающего:

| Компонент | Зачем | Источник | Способ | Нужны права администратора |
|---|---|---|---|---|

Для каждого компонента бери основной способ из манифеста и называй запасной.
Обязательные компоненты идут первыми. Уточнения:

- Компонент уже стоит, но версия старая: обновляй тем же способом, которым он
  поставлен (видно по пути к исполняемому файлу: `npm`, `%LOCALAPPDATA%\Programs`,
  `Program Files`). Второй способ создаст дубль в PATH.
- Навык лежит в `skills-disabled` того же клиента: план предлагает перенести
  папку в `skills`. Скачивание из источника нужно только при отсутствии
  локальной копии.
- У компонента пустой `source`: ищи архив `<имя>.skill` или папку навыка в
  текущем проекте и в разделе Releases репозитория; не нашёл - спроси
  пользователя.
- Зависимость из поля `requires` относится к другой ступени: проверь её и
  покажи в плане. Дождись подтверждения плана целиком или по
строкам. До подтверждения шаг 4 не начинается.

### 4. Установка

Ставь по одному компоненту в порядке плана:

1. основной способ из манифеста;
2. если он недоступен (нет winget, нет прав, отказ сети), запасной способ;
3. способ `release` выполняется скриптом
   [scripts/install_release.py](scripts/install_release.py): он скачивает архив
   официального релиза GitHub, проверяет SHA-256, если хеш указан, ставит в
   `%LOCALAPPDATA%\Programs\<имя>` и добавляет папку в PATH пользователя;
4. способ `skill` (навык агента) выполняется скриптом
   [scripts/install_skill.py](scripts/install_skill.py): поверхностный clone
   репозитория на закреплённом теге и копирование папки навыка целиком в каталог
   клиента (ZCode: `~/.zcode/skills`), либо распаковка архива `<имя>.skill`. Тег
   из манифеста не меняй: другая версия чужого навыка с этим набором не
   проверялась. Код выхода 3 означает, что навык уже стоит: обновление
   согласуй с пользователем;
5. способ `manual` выполняет пользователь: дай ему точную инструкцию из
   манифеста и жди подтверждения.

Навык из `skills-disabled` включается переносом папки в `skills` после
подтверждения пользователя. Вручную архив `.skill` распаковывается командой
`python -m zipfile -e <имя>.skill <каталог навыков>`: `Expand-Archive`
расширение `.skill` не принимает.

#### Пост-установка code-index

Способ `release` кладёт только бинарник - это не рабочее состояние: без
настроенных демона и транспорта MCP-клиент стучится в мёртвый порт 8011.
Сразу после установки, в той же сессии и после подтверждения пользователем:

1. Задать переменную окружения пользователя:
   `setx CODE_INDEX_HOME "%USERPROFILE%\.code-index"`.
2. Создать `%USERPROFILE%\.code-index\daemon.toml` с проектом выгрузки;
   путь с кириллицей - в одинарных кавычках:
   ```toml
   [[paths]]
   alias = "ut"
   path = 'C:\Users\roman\Projects\ut\src'
   ```
3. Запустить демон: `bsl-indexer daemon run` (сам остаётся в памяти) и
   дождаться готовности по `bsl-indexer daemon status`.
4. Поднять MCP-транспорт отдельным отсоединённым процессом - он не должен
   умирать вместе с сессией агента (порт 8011 по умолчанию):
   ```powershell
   Start-Process -WindowStyle Hidden bsl-indexer -ArgumentList 'serve','--config',"$env:CODE_INDEX_HOME\daemon.toml",'--transport','http'
   ```
5. Зарегистрировать MCP-сервер `http://127.0.0.1:8011/mcp` в клиенте агента.
6. Сквозная проба: JSON-RPC initialize, затем `get_stats`. Заголовки
   `Accept: application/json, text/event-stream` обязательны; голый `curl`
   без них получает HTTP 406 - это норма, не признак поломки. В Git Bash тело
   запроса с кириллицей - в UTF-8 файл и `--data-binary @файл`. Установка
   завершена только по прошедшей пробе.
7. В отчёт включить команды перезапуска (шаги 3-4): автозапуска нет, после
   перезагрузки Windows демон и транспорт поднимаются вручную или задачей
   планировщика.

### 5. Повторная проверка и версии

```bash
python scripts/check_env.py --stage <ступень> --client <клиент> --write-versions setup/versions.md
```

Путь `setup/versions.md` считается от корня проекта, в котором работает агент.
Установку считай завершённой только по повторной проверке, не по коду выхода
установщика. Сообщи, что программы, добавленные в PATH, клиент агента и открытые
терминалы увидят после перезапуска.

## Отчёт

- что было, что поставлено, каким способом и откуда;
- что осталось и почему (нет прав, блокировка ИБ, ждёт ручного шага);
- путь к `setup/versions.md`;
- что перезапустить.

## Частые ошибки

| Ситуация | Что делать |
|---|---|
| `winget` не найден | Запасной способ из манифеста; для релизов GitHub `install_release.py` |
| Chocolatey просит права администратора или пишет про lock-файл | Не повторять с правами; запасной способ без прав |
| `mmdc` есть, PNG не создаётся | Не хватает headless Chrome: `npx puppeteer browsers install chrome-headless-shell` |
| Программа установлена, клиент агента её не видит | PATH обновлён в реестре, клиент нужно перезапустить |
| Навык есть в папке другого клиента | Проверка с `--client` его не засчитает: копировать в каталог нужного клиента |
| Проверка показывает «проверить вручную» | Компонент без автоматической проверки: спросить пользователя или выполнить шаг проверки из его инструкции |
| code-index: статус «настроить» | Бинарник есть, но не настроена цепочка: выполнить пост-установку выше, не переустанавливать |
| `curl` к `:8011/mcp` отвечает HTTP 406 | Норма для запроса без `Accept: application/json, text/event-stream` и `mcp-session-id`: проверять JSON-RPC initialize, не curl |
| JSON-RPC из Git Bash: «invalid unicode code point» | Кириллица в аргументах ломает тело: писать JSON в UTF-8 файл и `curl --data-binary @файл` |
| `bsl-indexer daemon status` падает | Не задан `CODE_INDEX_HOME`: `setx CODE_INDEX_HOME "%USERPROFILE%\.code-index"`, перезапустить терминал |
| MCP-транспорт code-index умирает в конце сессии агента | `serve` запускать отсоединённо (`Start-Process`), не фоновой задачей сессии |
| `bsl-indexer stats` не находит index.db | Команда ищет `.\code-index\index.db` от текущей папки: запускать из корня проекта |
