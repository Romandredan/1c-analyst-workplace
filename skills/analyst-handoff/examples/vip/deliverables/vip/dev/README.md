# Пакет для разработки: выездная примерка для VIP-клиентов

**Изменение OpenSpec:** `add-vip-fitting-sales`. **Дата:** 2026-11-09.
**Вердикт:** не готово.

Расшифровка кодов (первое употребление в этом файле): Р-N - решение N в пакете для заказчика; ADR - запись архитектурного решения в `docs/adr/`; Б-N - блокер (раздел ниже); З-N - замечание к артефакту из `handoff.md`; В-N - вопрос для разработки из разделов 8-9 пакета для заказчика; Q-E1 - вопрос о сроке жизни ссылки, ответ не получен.

## Источники

- Пакет для заказчика: `deliverables/vip/customer/package.md`, версия 2, статус черновик (на согласование не отправлен). Решения Р-1, Р-2, Р-3, Р-6, Р-7, Р-8 подтверждены владельцем процесса письмом от 2026-11-09 (`docs/research/vip/05-подтверждение-заказчика.md`), Р-4 и Р-5 остаются «Предложено». - OpenSpec: `openspec/changes/add-vip-fitting-sales/` (`proposal.md`, `design.md`, `tasks.md`, четыре спецификации, девять требований). `openspec validate --strict`: пройдено.

## Блокеры

- **Б-1.** В `design.md` нет таблицы интеграций с колонками «Триггер», «Ошибки», «Повторы», «Владелец»; для приёма уведомления об оплате (задача 4.4) и создания ссылки не заданы ошибки, повторы, защита от дублей (В-2, В-3). Замечание З-1. Владелец: автор изменения OpenSpec; решения по В-2 и В-3: владелец не назван, назначить. Снимется: таблица заполнена, `check_package.py dev` не выдаёт ошибку по `design.md`.
- **Б-2.** У четырёх требований нет отказного сценария (З-2, З-3, З-4, З-5): «VIP-продажи используют отдельную кассу»; «Ссылка создаётся в отдельном мерчанте со сроком жизни дольше 20 минут»; «Уведомление об оплате приходит в 1С и привязывается к заказу»; «Заказ на примерку держит товар резервом без отдельного склада». Владелец: автор изменения OpenSpec. Снимется: у каждого из четырёх требований есть сценарий, в котором система отклоняет недопустимое действие (определение в `handoff.md`).
- **Б-3.** Срок жизни ссылки в требовании не задан числом (З-6), значение зависит от ответа банка (Q-E1) и от вопроса 2 пакета о предельном сроке ожидания оплаты. Владелец: владелец процесса; запрашивающий ответ банка не назван, назначить. Снимется: срок или правило его выбора получены и внесены в спецификацию автором изменения.
- **Б-4.** Сценарий «Чек по VIP-заказу уходит на отдельную кассу» и задачу 7.3 нельзя принять: создание реализации и чека вынесено вместе с Р-4, и изменение не порождает кассового документа (З-7). Владелец: автор изменения OpenSpec; решение по Р-4: бухгалтерия. Снимется: определён источник кассового документа в объёме изменения либо сценарий и задача 7.3 исключены до решения по Р-4.
