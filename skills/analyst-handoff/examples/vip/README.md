# Пример: продажа VIP-клиентам с выездной примеркой

Полный путь навыка на одном кейсе 1С: от письма заказчика и расшифровок встреч
до пакета на согласование и пакета для разработки. Папка устроена как корень
проекта, команды ниже запускаются из неё.

## Кейс

Магазин уже возит VIP-клиентам товар на примерку домой и принимает оплату
позже по ссылке, но процесс ведётся вручную, вне 1С; задача - автоматизировать
его. В постановке не определены момент чека, срок жизни ссылки,
судьба товара при неоплате и маршрут уведомлений об оплате. Кейс взят из
реальной практики, имена, компании и суммы изменены.

| Файл | Происхождение |

| `docs/research/vip/03-встреча-2-транскрипт.md` | Обезличенная расшифровка второй встречи |

| `docs/research/vip/05-подтверждение-заказчика.md` | Письмо-пример: подтверждение части решений, на котором показан режим «разработка» |
| `docs/adr/` | Два решения в статусе `proposed` |

Всё в `deliverables/` и `openspec/` сгенерировано агентом на модели Claude
Sonnet по инструкции навыка и не правилось вручную.

## Что смотреть

- `deliverables/vip/customer/build/vip-v2.html` - пакет на согласование одним
  файлом: решения со статусами, процесс по этапам, три схемы, риски на подпись
  с вариантом Б, открытые вопросы.
- `deliverables/vip/customer/CHANGELOG.md` - что изменилось между версиями.
- `deliverables/vip/dev/README.md` - вердикт «не готово» и четыре блокера.
- `deliverables/vip/dev/handoff.md` - замечания к изменению OpenSpec и ADR,
  которые режим «разработка» нашёл, но сам не исправлял.

Экраны форм (проход 3) в этом примере отмечены как «не требуется».

## Почему вердикт «не готово»

Пример намеренно показывает непройденную проверку. Изменение OpenSpec проходит
`openspec validate --strict`, но режим «разработка» находит то, что строгая
валидация не видит: у интеграций в `design.md` не заданы триггеры, ошибки,
повторы и владельцы, у четырёх требований нет отказного сценария, срок жизни
ссылки зависит от открытого вопроса. Пакет для разработки фиксирует это как
блокеры с владельцами и не пытается дописать спецификацию сам.

## Проверки

```bash
python ../../scripts/check_package.py customer deliverables/vip/customer
python ../../scripts/check_package.py dev deliverables/vip/dev --change add-vip-fitting-sales --customer deliverables/vip/customer
python ../../scripts/build_package.py deliverables/vip/customer
```

Первая проверка проходит без замечаний. Вторая завершается с ошибкой по
таблице интеграций в `design.md`: это и есть блокер Б-1 из вердикта.
