# Проверка пакета аналитика

Механические пункты проверяет `scripts/check_package.py`. Пункты, помеченные
«человек», проверяются чтением.

## Общие

- [ ] Факты отделены от предположений; предположения помечены `[ПРОВЕРЬ]`.
- [ ] Эталон не использован как скрытый источник ответа (человек).
- [ ] Статусы решений соответствуют подтверждениям: `Подтверждено` и `accepted`
      только после явного согласия человека.
- [ ] Открытые риски не выданы за принятые решения.
- [ ] Нет секретов, учётных данных и персональных данных из рабочих систем.

## Пакет для заказчика

Проход 1, текст:

- [ ] Текст пакета в одном файле `package.md`, разделы соответствуют профилю.
- [ ] Разделы для заказчика написаны языком бизнеса, без имён объектов метаданных.
- [ ] Каждое решение Р-N имеет обоснование, источник и статус.
- [ ] Каждый риск имеет владельца, последствия и вариант Б.
- [ ] В открытых вопросах только вопросы к заказчику и владельцам рисков.
- [ ] Места будущих картинок отмечены заглушками `D<N>` и `S<N>`, в манифесте
      указано, на чём основана каждая.

Проходы 2 и 3, диаграммы и экраны:

- [ ] Каждая заглушка заполнена картинкой, имя файла начинается с её идентификатора.
- [ ] Картинка совпадает с текстом; расхождение исправлено в тексте (человек).
- [ ] Картинка открыта и читается на странице A4 (человек).

Проход 4, сборка:

- [ ] DOCX и HTML существуют и не пусты; при отсутствии pandoc явно сказано,
      что DOCX не собран.
- [ ] Предупреждений о незаполненных заглушках нет.

Проход 5, правки:

- [ ] Версия увеличена, в `CHANGELOG.md` перечислены изменения и перестроенные
      картинки.

## Пакет для разработки

Входы:

- [ ] Изменение OpenSpec существует и проходит `openspec validate --strict`.
- [ ] Требования, сценарии и задачи находятся в OpenSpec, а не в пакете.

Покрытие:

- [ ] Каждое подтверждённое решение Р-N покрыто требованием.
- [ ] У каждого требования есть основной и отказный сценарий.
- [ ] Каждое требование есть в `traceability.md`, каждая задача связана с требованием.
- [ ] Для каждой внешней интеграции в `design.md` указаны триггер, данные,
      ошибки, повторы и владелец (человек).
- [ ] Труднообратимые решения имеют ADR и владельца (человек).

Вердикт:

- [ ] Блокеры перечислены с владельцами и условием снятия.
- [ ] «Готово к реализации» стоит только без блокеров и с пройденными проверками.

## Честность результата

- [ ] Не заявлена production-готовность.
- [ ] Не заявлена проверка, которая фактически не выполнялась.
- [ ] Не заявлена работа внешней интеграции без её запуска.
- [ ] Нет кода или изменений метаданных вне разрешённого процесса.
