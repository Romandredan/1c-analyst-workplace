# analyst-handoff

Навык для ИИ-агента аналитика: собирает пакет на согласование заказчику и пакет
для передачи в разработку из уже подготовленных материалов задачи. Сам навык
ничего не изобретает: он раскладывает решения, риски и вопросы по местам,
строит картинки из текста, собирает DOCX и HTML и проверяет, что ни одно звено
не потеряно.

Формат навыка совместим со спецификацией [Agent Skills](https://agentskills.io/specification):
`SKILL.md` с YAML-шапкой и вспомогательные файлы рядом.

## Где навык стоит в работе аналитика

```text
сырьё и встречи → извлечение требований → ответы заказчика → ADR и прожарка решений
  → пакет для заказчика (подпись) → изменение OpenSpec → пакет для разработки
```

Каждое знание живёт в одном месте:

| Знание | Где |
|---|---|
| Почему решили | `docs/adr/` |
| Что согласовал заказчик | `deliverables/<case-id>/customer/package.md` |
| Требования, сценарии, задачи | `openspec/changes/<change-id>/` |
| Связи от решения до задачи, вердикт готовности | `deliverables/<case-id>/dev/` |

## Режимы

| Режим | Когда | Что получается |
|---|---|---|
| Заказчик, итерационный | Согласование по шагам: сначала текст, потом диаграммы, потом экраны | Один проход за запуск, остановка после каждого |
| Заказчик, полный | Нужен полный документ за один запуск | Проходы 1-4 подряд с проверкой после каждого |
| Разработка | Передача в разработку после согласования | Карта ссылок, трассировка, границы и вердикт поверх OpenSpec |

Пакет для заказчика строится проходами:

1. **Текст** - `package.md` с заглушками `D<N>` (диаграммы) и `S<N>` (экраны).
2. **Диаграммы** - Mermaid по тексту, рендер в PNG.
3. **Экраны** - прототипы форм навыком прототипирования экранов.
4. **Сборка** - DOCX и HTML одним файлом с картинками внутри.
5. **Правки** - замечания заказчика вносятся в текст, затронутые картинки
   перестраиваются, версия растёт, изменения пишутся в журнал.

Профили пакета: краткий (шапка, решения, процесс, риски, вопросы) для раннего
согласования и полный (12 разделов, включая состояния, исключения, интеграции,
данные и критерии приёмки) для финальной подписи.

## Установка

В составе рабочего места навык и нужные ему инструменты ставит навык
[`analyst-workplace-setup`](../analyst-workplace-setup/). Отдельно навык
ставится из архива `analyst-handoff.skill` (раздел Releases репозитория; папки
`examples/` и `tests/` в архив не входят) или копированием папки
`analyst-handoff` в каталог навыков вашего агента:

| Агент | Каталог |
|---|---|
| Claude Code | `~/.claude/skills/` или `<проект>/.claude/skills/` |
| Агенты с поддержкой общего каталога | `~/.agents/skills/` |
| Другие клиенты | каталог навыков по документации клиента |

Инструменты:

| Инструмент | Зачем | Обязателен |
|---|---|---|
| Python 3.10+ | скрипты сборки и проверки | да |
| [pandoc](https://pandoc.org/installing.html) | DOCX и HTML | для DOCX; без него собирается только HTML (нужен `pip install markdown-it-py`) |
| [Mermaid CLI](https://github.com/mermaid-js/mermaid-cli) (`mmdc`) | диаграммы | для прохода 2 |
| [OpenSpec](https://github.com/Fission-AI/OpenSpec) | спецификация и её проверка | для режима «разработка» |
| Навык прототипирования экранов | экраны форм | для прохода 3; можно отметить проход как «не требуется» |

```bash
winget install --id JohnMacFarlane.Pandoc -e
npm install -g @mermaid-js/mermaid-cli
npm install -g @fission-ai/openspec
```

## Как вызывать

```text
Собери по кейсу vip пакет на согласование заказчику, итерационно.
Дальше.
Подготовь по кейсу vip полный пакет на согласование сразу целиком, нужен docx и html.
Заказчик прислал замечания, внеси их в пакет по vip.
Передай кейс vip в разработку.
```

Входы агент ищет в проекте: письма и расшифровки в `docs/research/`, ADR в
`docs/adr/`, изменения OpenSpec в `openspec/changes/`.

## Скрипты

```bash
python scripts/build_package.py deliverables/<case-id>/customer [--reference-doc шаблон.docx] [--draft]
python scripts/check_package.py customer deliverables/<case-id>/customer
python scripts/check_package.py dev deliverables/<case-id>/dev --change <change-id> --customer deliverables/<case-id>/customer
```

- `build_package.py` собирает `build/<case-id>-v<версия>.docx` и `.html`.
  Сборка останавливается, если в тексте остались подписи заглушек без картинок:
  заказчик не должен получить документ с «здесь будет схема». Черновик для себя
  собирается с `--draft`. Стиль DOCX задаётся Word-шаблоном `--reference-doc`.
- `check_package.py` проверяет форму и связи: разделы профиля, статусы решений,
  владельцев и варианты Б у рисков, заполненность заглушек, имена метаданных в
  разделах для заказчика; для разработки вызывает `openspec validate --strict`
  и сверяет трассировку с требованиями и задачами OpenSpec.

## Пример

[examples/vip](examples/vip) - полный путь на кейсе продажи VIP-клиентам с
выездной примеркой: входы (письмо, извлечение требований, расшифровка, ответы,
ADR), пакет для заказчика с тремя схемами и сборкой в DOCX и HTML, изменение
OpenSpec и пакет для разработки с вердиктом «не готово» и блокерами. Папка
`examples/` в архив навыка не входит.

## Что навык не делает

- Не пишет код, не создаёт mock API, не вызывает внешние системы.
- Не ставит `Подтверждено` и `accepted` без явного согласия человека.
- Не пишет требования и задачи вместо OpenSpec: без изменения OpenSpec режим
  «разработка» останавливается и называет пропущенный шаг.
- Не заполняет раздел, для которого нет источника: такой раздел становится
  открытым вопросом с адресатом.

## Состав

```text
analyst-handoff/
├── SKILL.md               # инструкция агенту: режимы, проходы, границы
├── customer-package.md    # формат пакета для заказчика: профили, разделы, заглушки
├── dev-package.md         # формат пакета для разработки поверх OpenSpec
├── review-checklist.md    # проверки по проходам и режимам
├── scripts/
│   ├── build_package.py   # сборка DOCX и HTML
│   └── check_package.py   # проверка пакетов
├── assets/package.css     # стиль HTML
├── examples/vip/          # пример полного пути (в архив навыка не входит)
└── tests/test_skill.py    # проверка навыка и регрессия на примере (в архив не входит)
```

## Проверка навыка

```bash
python tests/test_skill.py
```

Тест проверяет структуру и тексты навыка, запуск скриптов и регрессию на
примере: пакет для заказчика проходит проверку, пакет для разработки ловит
блокер по `design.md`, сборка выдаёт HTML и DOCX и останавливается на
незаполненной заглушке. Без openspec и pandoc соответствующие шаги
пропускаются.

## Что проверено и что нет

Навык проверялся прогонами агента на модели Claude Sonnet: итерационный режим
(проходы 1, 2, остановка перед следующим проходом), полный режим, проход правок,
сборка с pandoc 3.13 и Mermaid CLI 12, режим «разработка» с OpenSpec 1.16 и без
него. Не проверены: проход 3 с реальным рендером экранов, Word-шаблон
`--reference-doc`, другие модели и агентские клиенты, Python ниже 3.14.
